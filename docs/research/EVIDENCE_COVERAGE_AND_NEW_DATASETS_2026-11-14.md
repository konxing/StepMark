# StepMark 证据覆盖率与缺失敏感性升级（2026-11-14）

## 已落地代码（不改用户数据、不改线上评分）
- `packages/core/src/adherence-sensitivity.ts` 提供独立的、纯函数的 **recorded-data identification bounds（观测数据识别范围）**。输入仅包括已确认且归属同一用户/习惯的机会计数，不读取个人身份、数据库或网络。
- `auditHabitOpportunities` 新增 `adherenceSensitivity` 输出；保留原有 `observedAdherence` API 与 `habit-progress-v1` 评分不变。AI 推断仍只在临时/待核实层，不混入真实完成率。
- `knownEligibleOutcomeCoverage` 衡量已知合格机会中，有多少具备确定的执行结果。`knownEligibleIdentificationBounds` 把已知合格机会里执行结果缺失的记录分别假设为“未执行”和“执行”，得到下界与上界。
- `recordedEventConservativeBounds` 在上述范围基础上，将机会合格性未知的**已记录**事件也做最保守扩展。它刻意可以宽于最紧数学界，尤其当资格未知但执行已知时。**未记录的自然日不属于分母，不可能因此估算。**
- 显式“无合格机会”但“已执行”属于矛盾证据：现在拒绝这种事件，要求上游纠错，避免不可信记录进入汇总。
- 所有范围都不是 95% 置信区间，不表示总体长期依从率、用户养成概率或能力提升；重复行为有自相关和非随机缺报，不能直接把事件当独立二项样本。新的单元测试覆盖完全已知、部分缺失、全部缺失、AI-only、非法事件及边界。

示例：两次已知行为（完成 1、未完成 1）和另外两次已知合格但结果未知，原先可观察完成率是 50%；新范围为 [25%, 75%]，不是 50% 的精确估计。再加一次合格性未知的已记录事件，保守范围变为 [20%, 80%]。这些是基于**记录集合**的算术限制，不是关于未来的预测。

## 下一阶段真实数据准入步骤

1. 优先检查 openESM 数据集的 Zenodo 发行版本、授权、数据字典、缺失编码与任何隐私风险，固定下载文件 SHA-256。仅在独立 runner 内短暂载入，禁止提交个人级记录或对生产租户数据做统计。
2. 对 **Study 1** 事先规定“研究中排定且可辨认的提示数”为分母，以 `compliance` 计算响应率及按随机化/处理组的分层。验证 `beep` 与不同组实际排班一致后才能从未出现的行推断缺报；否则只报告“已记录行内缺失”。
3. 与研究采集频率相关的偏差最多支持“减少 StepMark 的问询负担、保留未知与低频回顾”的 UX 假设，**不**支持直接套用该样本的参数来更新用户习惯分。
4. 对认知 HFCA 数据必须先核对重测分量表的测量等价及是否存在学习效应，确认样本、任务、时间的对照条件，之后再讨论向 StepMark 的思维、注意、反应能力模块迁移。

原则：**无确切来源、许可或可重复指标时，结论必须是证据不足。** 这次升级没有引入第三方参与者数据、数据库迁移或新的 AI 外传权限。

# StepMark P3-B：从聊天到习惯证据的来源校验网关

代码：`packages/core/src/habit-chat-evidence.ts` 和 `test/habit-chat-evidence.test.ts`。

**定位**：纯函数、研究与安全准备层。当前没有新增数据库表、没有 AI 模型供应商调用、没有服务端 API 写入，也没有在 Web/微信小程序中偷偷启用自动记录或修改习惯进度。后续迁移前须另行确认安全/用户授权及旧数据兼容方案。

## 数据流

1. StepMark 的**可信会话服务端**决定当前登录用户 ID、所请求的习惯 ID/名称/用户设置的别名和来源消息。模型不允许自行选 owner，也不能跨用户列出习惯。
2. AI 可以提出一条机器可读候选：消息 ID、原文确切引句、UTF-16 起止位置、目标习惯 ID、是否遇到线索、是否有机会、是否执行及其推测的自然启动等级。
3. `prepareAiHabitChatClaim` 只接受用户本人发出的消息，校验当前用户与习惯所有者、消息作者一致；核验原文引句的**逐字符准确匹配**、消息/习惯 ID 对应、习惯名/别名必须在引句中出现，排除与结构语义明显矛盾的字段。
4. 未明确的机会/执行/线索是 `null`，**不能编码成 false 或零**。事件发生时间仍为 `null`，绝不把“聊天消息发送时间”推断成习惯实际发生时间。模型提议的自然启动等级也仍是 `proposedInitiationLevel`，不能伪装成经规范量表实测的自评。
5. 即使来源校验通过，结果仍标为 `kind="provisional_only"`、`source="ai_interpretation"`、`userReportConfirmed=false`、`requiresEventTimeResolution=true`。不会进入确认执行率分子或分母，**不会自动提交后端**。
6. 对“打算、明天、如果”等未来/假设表达，已知的否定冲突、他人陈述添加提示标记。匹配规则并非完整的中文 NLP 语义识别，不会当作确定真值或自动加分依据。

## 安全和误读测试

- 跨账号 / 跨习惯 ID / AI 或助手发言冒充用户发言：拒绝。
- 伪造引用、偏移不匹配、缺乏习惯名称的“做了训练”：拒绝。
- “我明天打算练”“今天还没练”“朋友练了”等：即使候选仍可展示，也仅是 **provisional**，附加语义风险标志，不得写入已确认用户行动。
- AI 在聊天中看见个人健康、职业、私密内容，不意味着得到训练、外传或跨应用的许可。旧有选择性授权行为保持不变。
- 同一条用户消息可能含多件事、过去/未来混合、引用别人的话或含否定；当前**不保证**识别所有歧义，未来需要中文语义样本和用户能够低负担纠错的设计。

## 面向“尽可能减少用户操作”的后续方案

- 默认使用用户现有对话的明确陈述作为候选，不要求每次填写复杂表单。
- 下一阶段建立来源到数据库的**分级写入权限**：直接用户显式结构化记录可以事务/幂等写入；不含确切时间或有歧义的 AI 候选不能静默写入。是否可在明确授权和可回滚情况下进行“无需逐条确认”的自动写入，须与隐私/误判测试一同设计并审核。
- 必须先建立消息、用户、习惯、机会记录的所有权边界，支持撤回、版本冲突、纠错历史及审计可追溯性；数据库迁移与后端任务调度不能在本研究准备阶段擅自启动。
- AI 模型不能自评自己的正确性；在标注过的真实中文聊天用例上建立 **precision / recall / 错误写入率** 与多用户越权红队测试，才考虑写入产品。

以上约束由模块接口和自动测试固化，但自动测试通过**不等于**模型已经可以科学判断人的习惯形成，也不意味着外部 AI 识别已上线。
